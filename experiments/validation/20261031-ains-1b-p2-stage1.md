## Corrections to v2 (reviewer points, all accepted)
1. DESTRUCTOR double-free fixed: ONE call per owner. LAYOUT (confirmed
   by main 20:51 after verifier contrast 20:51:26): the runtime's NATIVE
   8-byte-header convention, same as DArrDyn - payload = DATA pointer
   (cells), count at -8(DATA), block = 8 + count*16 bytes from DATA-8.
   Destructor = hbc_dfree(DATA, live_count) VERBATIM: it frees tag-4
   cell payloads then hbc_free(DATA, 16), whose size is validated by the
   instrumented registry; no new runtime helper, no custom free.
   REGISTERED LIMIT: -8(DATA) is the allocation CAPACITY; in stage 1
   (exact literals, no resize) live count == capacity. Before
   AIns/ASize/ADel pieces the header needs a live-vs-capacity redesign;
   do not generalize "header count is Len". (Verifier correction to my
   justification: NOT everything in the runtime uses 8-byte headers -
   strings use 16, hashes use 16; only the DArrDyn ABI is the relevant
   one, and it is the right representation for scalar cells.)
2. AView bridge (the only cross-call route in stage 1): at the call
   site, cg emits a runtime guard slot-tag == 8 (registered error
   otherwise) BEFORE dereferencing -8(DATA), then builds the EXISTING
   24-byte caller-frame header {kind=1, ptr = DATA, len = count} exactly
   like a typed DArrDyn today. NO new runtime helper, NO tag6 from a buffer, NO
   fabricated headers. Callee cell reads reuse the existing aview
   machinery (kind 1 = 16-byte tag/payload cells, which matches the
   layout at base+16). Stage-2 note (not built): a cell-8 read under an
   AView needs a new kind or constructor route producing a complete
   caller-frame tag6 header with borrow life.
3. Stage-1 transfers: assignment-transfer from array LITERALS only.
   NO call results, NO x := f(x), NO Dyn array param/return, NO AClone.
   Reassignment: evaluate RHS fully -> free the slot's old value (tag4
   string -> freestr; tag8 -> hbc_dfree verbatim) -> install {8, base}. Scalar to
   array and array to scalar both free the old value. Self-assign
   x := x: compile-time identity -> explicit no-op (typed families'
   measured move untouched).
4. Checker minimum: a DEDICATED acceptance of an array literal into a
   Dyn slot (no generic type_expr widening that could escape the
   slot). REJECTED in stage 1: storing a cell into a variable, any
   return of a view/borrow, x := y aliasing, captures, self-root
   mutation/move through indices or sibling items (same family as the
   existing guards). OUTPUT BORROW INTERVAL: a borrowed Dyn-array
   expression in a print statement keeps its owner frozen until the
   LAST RENDER of that statement, not the last eval - the consumer
   evaluates all items before printing, and the checker models that
   whole interval. Mutating-callee and resize routes over a Dyn owner
   stay OUT until pieces 2/3 implement their checks.
5. Cell mutation a[i] := scalar on a Dyn-held array: bounds-checked,
   RHS evaluated first, old cell payload freed when tag4, retag in
   place (0/1/3/4 only; an array RHS cell-write is rejected in stage 1).
6. Epilogue: an OWNER Dyn slot frees tag4 and tag8 exactly once on
   every exit path (branch/loop/early-return), proven with hb_memcheck;
   AView params free nothing (existing static behavior).
7. Claims discipline: stage 1 = "P2 infrastructure for the scalar part
   of bare-LOCAL arrays". It is NOT "ains L11-57 covered": AClone,
   AIns/ADel/ASize/AFill and the item-capture contracts are still
   missing (pieces 2/3).
8. Stage 2 (designed as goal, NOT built now): tag8 owned children +

## Alias differential (main 21:01 clarification, binding)
The contract promised a CHECKER rejection of x := y aliasing. When both
slots are Dyn the array-ness of the source is statically INDETERMINABLE
in the current model, so stage 1 ships a RUNTIME guard instead:
- Where the owner/tag-8 state IS statically known, the checker rejects
  (no free, no transfer before the rejection) - e.g. storing a cell
  read, returning a view, nested literals, computed items.
- Where it is not (Dyn <- Dyn Var copy), cg_dyn_clone_if_str leaves a
  tag-8 payload untouched (no free, no transfer), then the guard
  cmp $8 / je hbc_type_error fires BEFORE any free-old or store: at the
  error both slots still own their original values; the process exits
  rc1 without freeing or transferring anything. No double-free, no
  leak-by-ownership (process exit under the instrumented registry).
- rc1 clean is a REGISTERED FAILURE MODE, not Harbour compatibility
  (Harbour SHARES the array: oracle r6 b[1]:=77 -> a[1]==77) and not
  closure of the nominal compile-time rejection; a later stage (AClone
  or tracked flow) closes that gap. Fixtures must label it this way.
