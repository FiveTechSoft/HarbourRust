# ains piece 1b - P1 correction (print flush-trim), review snapshot 31Oct ~20:34 CET

SCOPE: QOut/QQOut trailing-space trim moves from per-statement last-item
right-trim to Harbour's flush model: a trailing string's spaces are HELD
(hbc_pending) and resolved by the next output - newline (a later `?`'s
leading newline) and OutStd DROP them, `??` content RE-EMITS them, OutErr
(stderr) never touches them, program exit drops them (q9/q10).

## Oracle basis (Harbour @694428e1, hbmk2 -gtstd, local probes only)
q1-q17 matrix + q18-q21 edge probes (probes/ains-preblockers01, oracle
binaries + outputs preserved): items joined by ONE separator space in
both `?` and `??` (q1/q3); string items keep trailing spaces mid-line
across `??` boundaries (q5-q7, q15, q16, q20); trim happens ONLY at
line flush - newline (q4/q14), OutStd write (q11, drops without
emitting), program exit (q9/q10); OutErr is a separate channel (q12/q15);
called functions printing `??` mid-line re-emit the hold (q20); an
EMPTY or BARE `??` must NOT re-emit (q18/q21 - caught and fixed in the
refinement). The cg comment's old "hk274-hk276" `??` trim claim had no
preserved probes (introduced 93035a65) and is FALSIFIED by q3/q6/q7;
comment corrected in src.

## Implementation (src/hbc.rs, this commit)
- hbc_pending (.data, next to hbc_trace_top, both targets).
- hbc_pstrt: prints a string right-trimmed and HOLDS the trimmed count;
  re-emits a previous hold first only when it will write bytes itself
  (the %rdx length is saved across the internal hbc_pflush call - a
  first-pass clobber lost it and the q1 probe caught the missing "b").
- hbc_pflush: emits the held spaces and clears the hold.
- cg_print_items: `?` zeroes the hold before its leading newline; OutStd
  (raw, stdout) zeroes it; OutErr untouched; `??` emits nothing at
  fragment start. Every render site that writes flushes first: bare
  before separator/int/dyn/dynlit/dyncell/f64/bool prints, guarded by
  len>0 before string prints, inside the NIL branches of darrs_elem /
  darr2_child, and inside pstrt for the last string item. The stderr
  (eprint) fragment keeps the old inline rtrim - its trim semantics are
  UNPROBED beyond q12/q15; pending state is stdout-only. New helpers
  avoid the hbc_print_ prefix so the eprint generator never copies them.
