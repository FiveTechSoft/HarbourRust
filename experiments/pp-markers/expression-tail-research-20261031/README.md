# Plain-tail inline translation: oracle research only

Own sources,pinned Harbour oracle.66expression-tail boundaries,27result
adjacency probes,44repeated-capture/result-context controls. No production code.

Arithmetic/calls/indexes remain in the tail capture;adjacent words,commas and
closing parentheses bound it. Harbour preprocessing can capture incomplete
expressions too;our future conservative grammar need not admit all of them.
Arrays,macros,codeblocks,aliases,dates and other ungrounded atoms must not be
silently treated as a supported arithmetic subset.

An initial hypothesis that result adjacency changes the capture is NOT proven.
Repeated <b> in `<a>_<b> + <b>` with New+7 preserves the complete expression
in both insertions. Different output for nested JOIN in concatenated results
can be due to rescanning in its new context. Do not turn that hypothesis into
an implementation instruction. Preserve all nested counterexamples.

Next candidate should use complete bounded expression captures and rescan,
then compare nested result contexts with the oracle. RealMTHNAME uses this
plain tail;identifier-only implementation is not whole-helper support. No
header/runtime/class/ABI/ownership/main or size/speed claim.
