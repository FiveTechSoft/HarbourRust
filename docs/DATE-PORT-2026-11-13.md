# Date/CToD port to the current compiler ABI

Status: local candidate, awaiting independent review. Base experiment commit:
`46e465228aac8009f85301be0d4585715b40315e`. This is an independent MIT
increment, not a merge of the old Date implementation into the new ABI.

## Contract

- `Date()` and `CToD(string)` produce a separate Date scalar. Locals,
  assignment, same-Date comparisons, Date-returning functions, `Empty`,
  `ValType` and existing output channels are covered in the bounded forms tested.
- Own representation: eight-byte packed YYYYMMDD, zero for empty. It does not
  reuse the older Date implementation's calendar payload or algorithms.
  Existing I64/display-provenance slots stay 16 bytes; Block and Dyn ABIs do
  not change. CToD consumes then releases owned temporary strings.
- Independent byte-oriented parser, calendar validation and formatting were
  written against black-box observations. No Harbour implementation source is
  translated. Gregorian month lengths/leap divisibility are implemented directly.
- Default CToD behavior measured here: up to three digit runs, unsigned32
  modulo accumulation, nondigit separators, NUL ends the input, years below 100
  add 1900. Output is mm/dd/yy; empty dates render two blank fields/separators.
  This is not configurable SET DATE/EPOCH support.
- Ten older own rejection fixtures remain conservative: Date parameters/byref,
  arithmetic, mixed comparisons/assignment/returns, array/hash storage and
  malformed calls are not newly supported. General Dyn Date storage is not
  added. Both LLVM modes reject Date; ordinary Windows code generation alone
  does not establish Windows correctness.

## Explicit Date() limits

Linux preserves the old UTC contract. The native helper reads Linux syscall 201
and independently converts days from 1970 using year/month iteration. It does
not read the local timezone. UTC measurement passes, but live TZ=Etc/GMT-14
produces a different day from Harbour in the recorded evening sample. This is
an acknowledged compatibility limit, not an oracle match in arbitrary zones.

Windows emits GetLocalTime and reads SYSTEMTIME year/month/day, but no Windows
object/link/runtime check was possible with the available local installation.
No native Windows or Wine pass is claimed. Synthetic Linux clock substitutions
are tests of the conversion, not end-to-end clock or Windows evidence.

Persistent-root/@STATIC validation, retention and storage are not part of this
increment and were not extended. Their implementation is unchanged. Windows,
local-time Linux Date, configurable date formats, dates in general dynamic
containers and full application compatibility remain unverified/unsupported.
