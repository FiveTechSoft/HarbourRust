# Native ARM64 Mach-O backend (Apple Silicon), 16 November 2026

`--target=macho-arm64` (the default for an hbc built on Apple Silicon)
now writes a native arm64 Mach-O executable instead of rejecting.

## Design

hbc's code generator and its runtime emit one fixed x86-64 subset, the same
text the own assembler `hasm` encodes. `src/harm64.rs` (a child module of
`hasm`, reusing its parser) translates that subset instruction by instruction
into AArch64 at compile time. There is no run-time emulation and no x86 code
in the executable.

- Registers: x86 GPRs map to fixed ARM registers; `rsp` is x28 and addresses
  an emulated stack (64 MiB, mmap'ed at start-up), so push/pop/call/ret keep
  their 8-byte slot layout. `call` stores the return address in that slot and
  uses `bl`, `ret` reloads it and uses `ret`, so the hardware return predictor
  still works. xmm0-15 map to v0-v15. The real `sp` is only used to call
  libSystem.
- Flags: no flags register is emulated. A backward search over the control
  flow graph pairs each consumer (jcc, setcc, cmovcc, sbb) with its producers;
  only those producers use flag-setting ARM forms, and the condition is mapped
  through the producer kind (subtract, add, logic, inc/dec, imul overflow, FP
  compare, bit test, shift). Unknown or mixed pairings are compile errors.
  Translations that clobber NZCV internally preserve it when flags are live.
- System calls: Linux numbers are lowered to Darwin `svc #0x80` at compile
  time (write, open with flag conversion, close, mmap, munmap, exit, fcntl,
  gettimeofday). Anything else is a compile error.
- x87: the runtime only uses four fixed x87 idioms (pow, exp2, y*log2(x),
  fmod). They become calls to libSystem `pow`, `exp2`, `log`/`log10`/`log2`
  and `fmod` through one register-preserving wrapper.
- Mach-O: own writer. PIE, `__PAGEZERO`/`__TEXT`/`__DATA`/`__LINKEDIT`,
  dyld info rebase (absolute pointers in data) and bind (libSystem imports),
  `LC_MAIN`, `LC_BUILD_VERSION` (macOS 11), and an ad hoc SHA-256 code
  signature. No Apple linker, assembler or codesign is used.

## Evidence

- All 1209 runnable manifest rows (pos, posx, pos2, posx2, streams,
  streams2) compile with `--target=macho-arm64 --instrument` and produce the
  exact Linux expected bytes and exit codes when run under a Unicorn arm64
  user-mode harness with a Darwin system-call model: 1209/1209, counted twice
  (runner summary and results file).
- x86 Linux and Windows assembly is byte-identical to `origin/main` for all
  1822 manifest programs on both targets (3644 compilations).
- capstone disassembles every emitted word (no invalid encodings).

The emulator proves instruction semantics, not Darwin loader or kernel
acceptance. `tests/run_macho_arm64.py` is the native runner for Apple Silicon
hardware (CI or a Mac): it compiles every runnable row, runs it natively and
applies the same acceptance rules as `tests/run_battery.sh`.

## Not yet ported on Mach-O (rejected at compile time)

DBF (the gcc runtime computes syscall numbers at run time and uses Linux
`stat`/`flock` layouts), threads (no `clone` on Darwin), EXTERNAL, and
FILE/SET DEFAULT/PATH. These are the next increments.
