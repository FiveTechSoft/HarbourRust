# SubStr: bounded native byte-string support

`SubStr(cText, nStart [, nCount])` accepts typed strings and signed integer
positions/counts on the ordinary x86-64 backend. The result is an independent
owned string. Linux and Windows PE under Wine are execution-tested here.

Measured against Harbour 3.2.1dev, source `694428e1`:

- Positions start at 1. Position 0 also starts at the first byte.
- A negative position counts back from the end. A position before the
  beginning clamps to the first byte; one after the end produces empty text.
- Omitting the count takes the remainder. A nonpositive count produces empty
  text. A count beyond the end is clamped to the available bytes.
- These are byte positions, including embedded NUL and high bytes. This is
  not a Unicode-character or codepage-aware substring implementation.
- Arguments evaluate once, from source to position to count. The source is
  copied before evaluating later arguments, so a by-reference change to its
  original owner does not invalidate the retained source value.

The implementation reuses the current owned-string allocation, copy and
release helpers. It does not add Harbour runtime code or a new value tag.
An internal snapshot and the result copy are separate allocations; no speed
or allocation-count improvement is claimed.

## Reproduce

Build `hbc` normally, then run:

```sh
python3 tests/substr/check.py --compiler ./hbc --hbmk2 /path/to/hbmk2 \
  --output /tmp/substr-check
```

Add `--wine /path/to/wine --wine-prefix /path/to/prefix` to execute Windows
PE outputs too. The output directory must be new. The checker compiles the
same eight source programs with real Harbour, checks their recorded output,
and compares stdout, stderr and exit status without newline normalization.
Seven separate diagnostic wrappers release their owners before checking
`hb_memcheck() == 0`. A generated program covers 312 position/count/data
combinations; those are cases within one program, not 312 compiler tests.
Twelve named rejections preserve the bounded type/arity contract. The checker
also records the caught-error probe below separately as a known limit; it
is not counted as a passing compatibility case.

`tests/substr/manifest.txt` has 27 standalone regression entries: eight
same-source positives, seven memory wrappers and twelve negatives. It can
be passed to the existing native-manifest runner independently of the main
manifest. The fresh differential checker also runs the generated grid.

## Limits

This is not complete Harbour `SubStr` compatibility. Float-to-integer
conversion of positions/counts, Dyn-held strings/numbers, optional NIL,
extra arguments, Unicode/codepage-aware functions and abbreviated builtin
names are not admitted by this increment. Existing consumer limits still
apply: for example `ValType(SubStr(...))` is rejected by the general
`ValType` expression restriction, whereas `ValType(resultVariable)` works.
Left/Right/At/RAt, general string subtraction and other library functions
are separate work. LLVM and native ARM64 keep their named rejections.
No native Windows or macOS execution is claimed, and no tracked/released
compiler snapshot is rebuilt by this source patch.

The existing TRY sequence unwinder does not release owned expression
temporaries on an exception. If evaluating a later SubStr argument throws
to a CATCH, its already-created source snapshot is such a temporary and
leaks. A reproduced bound-error case returns normally from CATCH but has
final `hb_memcheck() == 1`, not 0. The standalone source is
`tests/substr/limits/caught-error.prg`; the checker records its balance but
does not make a nonzero leak a desired regression expectation. This is an explicit error-path limitation,
not an exception-safety claim. Normal-return paths in the memory wrappers
have final `hb_memcheck() == 0`. A full owned-unwinding fix is separate work.
