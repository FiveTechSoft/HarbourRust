# Loop register promotion (20 November 2026)

Phase 2 of tightening hbc's generated assembly (phase 1:
[PEEPHOLE-2026-11-19.md](PEEPHOLE-2026-11-19.md)). hbc keeps every local
in its rbp frame slot, so a loop that updates an integer accumulator
stores it to memory and loads it back on every iteration. That
store/reload chain, more than the instruction count, is what bounds hot
integer loops.

`src/loopreg.rs` runs on the final assembly text after the peephole pass.
For each statement loop (FOR `.Lforc_*`..`.Lfore_*`, WHILE
`.Lwhile_*`..`.Lendw_*`) whose body is straight inline code, it keeps the
8-byte words of some frame slots in registers for the duration of the
loop. `--no-loopreg` turns it off.

- Each chosen slot is loaded into its register right before the loop
  head label; the head is only reached by fall-through from outside.
- Every access to the slot inside the loop becomes the register.
- Every jump that leaves the loop (loop end, EXIT, RETURN, overflow and
  bound error handlers) goes through a stub that stores the written slots
  back first, so code after the loop, error handlers and RECOVER see the
  frame exactly as before.

## When it applies

A loop qualifies only when, between its head and end labels, there is no
call, ret, indirect jump, string instruction, directive or comment, no
memory access through a base other than rbp/rsp/rip, no indexed rbp
access, and no label referenced from outside the loop.

A slot qualifies only when every access overlapping its 8 bytes inside the
loop is the exact operand `-N(%rbp)` in a plain 64-bit integer form (mov,
add, sub, cmp, test, and, or, xor, imul, inc, dec, neg, not), and its
address is never taken (`lea -N(%rbp)`) anywhere in the function. Slots
that are read and written in the loop get registers first, then read-only,
then write-only slots.

Registers come from r8, r9, r10, rsi and rdi, minus any the loop names.
Without calls no ABI rule applies inside the loop. rsi and rdi are
callee-saved in Win64, but hbc code uses its own SysV-like convention on
every target: `hbc_fn_*` bodies already clobber them, the runtime blobs
entered from C follow the same convention, and the Win64 entries never
return to C. Every output form already appears in generated code with a
register operand, so the ELF/PE/Mach-O writers and the ARM64 translator
see no new instruction shapes.

## Measured (native Windows 11, 20 November 2026)

Integer loop of 200 million iterations (`s := s + i * k - 1` with a
conditional subtract), against the same compiler with the pass off. The
machine was loaded, so CPU time charged to the process was measured
instead of wall clock: two independent methods, 15 interleaved runs each,
minimum.

| method | without | with | change |
|---|---|---|---|
| process cycles (`QueryProcessCycleTime`) | 2.122 G | 1.656 G | -22 % |
| process CPU time (`TotalProcessorTime`) | 656 ms | 516 ms | -21 % |

Programs whose loops do not qualify get byte-identical assembly (`fib` and
a float `%` loop, for example).

## Coverage and verification

Over the runnable manifest rows (1264), 17 of 152 statement loops qualify,
in 13 rows: most loops contain a call (output, string or array helpers) or
reach memory through a pointer. The same 13 rows change for the Windows
target, the Linux target and with `--instrument`.

- Those 13 rows: compiled by main's compiler, by the peephole compiler and
  by this one, Windows PE run natively; stdout, stderr and exit status are
  identical in all three, plain and with `--instrument`, and the Linux ELF
  assembles with each.
- `tests/loopreg/programs/edges.prg` is a new manifest row covering EXIT,
  LOOP, nested FOR, WHILE, RETURN from inside a loop and a negative STEP,
  so the CI batteries run promoted loops on Linux, Windows and both macOS
  targets.
- Six unit tests in `src/loopreg.rs` cover the transformation, the stubs
  and each rejection rule.

## Next

Wider coverage needs knowing which pointers cannot reach the frame (array
loops), and keeping a value in a register across a call needs callee-saved
registers that every runtime helper preserves. Both belong to the code
generator rather than to a text pass.
