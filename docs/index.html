Rust architecture.

HarbourRust is an ahead-of-time compiler for Harbour, written in Rust. It translates Harbour source directly into x86-64 assembly and produces native executables: no VM, no interpreter. Support grows construct by construct, with byte-for-byte checks against the original Harbour compiler wherever applicable and explicit records of known differences. Unsupported syntax is rejected explicitly at compile time.

Project snapshot: 13 November 2026. Support and known differences are documented below.

Compatibility comes before speed claims. The reviewed compiler admits 31 of 1,041 unchanged upstream PRG files. Only 29 of those 31 fresh runs match exactly; two error-dialogue timeouts are not passes. Most of Harbour is still outside this subset.

How it works

One front end, two code-generation paths.

The compiler, hbc, is written in Rust. Its ordinary path performs its own analysis and emits assembly. Your Harbour program does not pass through rustc on that path.

1. Harbour source and preprocessing

Own preprocessor handles the implemented directives and transformations. Unsupported forms remain explicit limits, not a claim of full preprocessor compatibility.

↓
2. Tokenizer, parser and semantic analysis

Build a syntax tree, infer/check the supported types, and run the compiler's own move, ownership and borrowing checks. Reject unsupported forms before code generation.

↓
3a. Ordinary x86-64 backend

Emit assembly, then use GNU as and ld for the Linux executable. Windows uses a separate binutils/API path with its own verification limits.

3b. Experimental LLVM backend

A separate, bounded scalar AOT path selected with --experimental-llvm. It is included in main as an explicit experimental option and does not support everything the ordinary backend accepts.

↓
4. Native executable with a small runtime

The ordinary Linux path links its own freestanding helpers and uses system calls. No Harbour VM is required. This is a small embedded runtime, not "no runtime".

Rust-inspired, not Rust by inheritance.

Being written in Rust does not automatically make generated programs memory-safe. hbc implements its own rules and runtime. Its ownership model is deliberately different from Harbour's unrestricted dynamic sharing in some cases; that remains compatibility work.

A different trade-off from harbour/core.

Harbour's established compiler and runtime support a much broader dynamic language and ecosystem. HarbourRust explores a smaller native path. The aim is familiar Harbour syntax and tooling, without pretending the current subset has equivalent capabilities.

Historical evidence, not a universal promise

What the measurements actually show.

On two small Linux x86-64 programs, the recorded native path ran faster than the two measured Harbour configurations. These results are from 25 October 2026, not benchmarks of today's HEAD, real applications, or the experimental LLVM backend.

One comparison was withdrawn. b1_int took different numeric type paths in Harbour and HarbourRust. Its timing must not be presented as a speedup. Small benchmarks cannot establish that one language is generally faster.

Much smaller artifacts in the recorded Linux sample.

For the function-call benchmark, the historical unstripped ELF sizes were 9,032 bytes for HarbourRust, 1,431,608 bytes for Harbour pcode, and 1,431,560 bytes for Harbour -gc3. The Harbour binaries include the broader Harbour RTL and depend on libc/libm; the HarbourRust sample has a much smaller freestanding runtime. These are different capability sets.

Size record: 25 October 2026, HarbourRust 99f32d8f, Harbour 694428e1. This is a different HarbourRust revision from the timing rerun above. No Windows size ratio is claimed. Artifact sizes, versions and linking details.

Know the boundary

Working toward Harbour compatibility.

31 / 1,041

Upstream originals admitted

Reviewed compiler snapshot, 13 November 2026: 31 of 268 originals under upstream tests/, or 31 of 1,041 in the full inventory. Compilation is only a first gate. Fresh executions: 29 exact matches and two timeouts.

Early-stage

Integrated source, bounded results

Main integrates the reviewed compiler and the independent Date/CToD port. The local regression result is 1,657/1,661, with the four inherited failures t110, t385, t419 and t592. Linux Date() remains UTC, not local time. Regression counts are not percentages of language compatibility.

The goal is for all 1,041 originals and the project's own examples to build through familiar hbmk2 + hbc tooling and behave correctly. That is a target, not today's capability. Unsupported dynamic behavior, platform differences and backend-specific limits remain explicit.

Try the implemented subset

A short Linux build path.

From a checkout, with Rust and GNU binutils installed:

rustc --edition=2021 -O src/hbc.rs -o hbc
./hbc tests/samples/hello.hb hello.s --target=linux
as -o hello.o hello.s
ld -o hello hello.o
./hello

Building the compiler uses Rust's standard library. To use the prebuilt Linux or Windows compiler and build supported native-only examples, neither Rust nor a C compiler is needed: use GNU as/ld (MinGW-w64 binutils plus KERNEL32 on Windows). The release also includes ready-to-run Windows samples, smoke-tested under Wine 11.0, not real Windows. Older repository binaries may not match HEAD.
