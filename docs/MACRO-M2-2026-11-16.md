# M2 macro calls: Upper, Lower, Round

## Scope and limits

This increment adds an extensible runtime call boundary for Upper, Lower and Round to the existing contextual scalar macro evaluator. It preserves the parser, numeric operators, compiler writers and MEMVAR ownership rules from d0b102abe44d8caa6ffbba9fad5d1fb5fbdcfb40. No existing design document is replaced.

Limits: only these three builtin names dispatch. Case conversion is ASCII, not locale/codepage/Unicode parity. Calls have a maximum of 64 arguments; 65 fails with a named M2 capacity error, never silent truncation. Round's numeric decimal argument is truncated toward zero and must produce -15..15; values outside the interval (-16,16), including NaN, fail with a named M2 limit before the production helper. Unknown calls fail with a named M2 limit after evaluating their surviving arguments. Other evaluator limits and unsupported syntax remain unchanged. No recoverable Harbour ErrorBlock or user-code invocation is added. No Mach-O execution gate was run for this increment.

## Evaluation boundary

The parser builds a complete AST before lookup or evaluation. Call arguments use linked N_ARGUMENT nodes, distinct from grouped comma expressions. The fold pass has no lookup access. Literal first-string Upper/Lower calls may fold away unused extras, including unresolved names, as the pinned Harbour oracle does. Calls above the 64-argument limit are not folded away by this optimization.

Runtime calls evaluate all surviving arguments left-to-right, including ignored extras, before builtin arity/type checks. Argument results are copied or transferred into compiler-owned Dyn16 cells; the scratch vector uses the evaluator storage allocator. Argument cells and vector are released on every checked exit. Production helper return strings transfer ownership; float bits and metadata are copied before their temporary production allocation is freed. Fatal builtin frames are deferred until AST, scratch, bindings and frames have been destroyed.

src/macro_call_shims.s dispatches builtin IDs 1,2,3 to actual hbc_upper, hbc_lower and hbc_round/hbc_float_new helpers. It preserves internal SysV nonvolatile GPRs and restores either caller stack parity. It is not an external Windows ABI entry point.

The builtin names are a contiguous char array, not a pointer table. Generated code has no symbolic movabs or symbolic .quad/.long addresses. Existing PE fixed-base/NX policy is unchanged; no ASLR claim is made.

## Generator

The committed recipe pins MinGW GCC 10-posix 20220113 and all source dependency hashes. Existing small-code-model flags from BASE remain. GCC 10 emits one unsupported memory push despite -mno-push-args: pushq -8(%r10) is lowered to exact GAS bytes 41 FF 72 F8. movupd copies are converted to movdqu, the same unaligned 128-bit load/store operation, without interpreting the bits. evidence/generator-encoding.objdump records independent GNU-as encodings. Regeneration reproduced generated/hrmacro.s byte-for-byte, SHA256 2e16431ec89c7f62edf309189af6b298e7457a523f288233452829188b2e1c06.

## Evidence

Final tested compiler SHA256: f7710cde87065e30f51900020f77f00d86947441bcff7802a7a30ba9554b0841. A repeat build using rustc 1.100.0, edition 2021, opt-level=1, debuginfo=0, strip=symbols reproduced this hash. This is a Linux-hosted compiler emitting both ELF and PE, not a newly built Windows-hosted compiler.

- Full 1743-row manifest compiled/captured against BASE on ELF and PE: zero raw stdout/stderr/exit regressions. These full runs use external GAS/ld to execute captured assembly, not the internal writers. Complete compressed assembly and emission diffs are retained. Five macro-related emission changes per target.
- This is not a claim that the old manifest is raw-green: 66 ELF and 75 PE inherited raw fixture mismatches remain, plus 12 inherited compile-blocked PE positives. The secondary newline-tolerant column has zero mismatches but is not the primary verdict. See evidence/battery-summary.json for every row and affected source.
- Autonomous internal-writer mixed and values positives: four raw-exact comparisons to official Harbour. Embedded NUL, empty strings, ASCII boundaries, nested calls/macros, fractional/negative decimals, constant elimination, ignored extra arguments, 1000 repetitions and final hb_memcheck=0. Oracle sources replace only the non-Harbour hb_memcheck() harness call with 0; production still executes its actual check.
- Sixteen terminal error/ordering cases on each target: exact raw comparison to pinned Harbour, including missing tenth argument, syntax before lookup, type errors and UPPER/LOWER/ROUND frames. Authoritative rows are evidence/m2-fatal/{linux,windows}/results-00-16.json. Older partial rows and Wine startup contamination are retained but superseded, not counted as passing evidence.
- Eight ELF and eight PE arity/range/unknown controls. Round +/-16 intentionally differs from Harbour through a named stage limit; unknown oracle UI was not executed. Those rows are capacity controls, not parity claims. PE successful controls match the ELF controls, whose successful cases match Harbour.
- Host fault harness: 96 raw plus 96 compiler-allocation injection steps for M2; every fatal callback asserts raw/compiler pools, scratch, frames and bindings already zero. ASAN+UBSAN with leak checking exits 0 and empty stderr. Native PE host also exits 0 with empty stderr. Its C dispatch stub proves lifetime/cleanup, not production rounding semantics.
- ABI harness executes real production dispatch/helpers on both targets, all IDs, both stack parities, RBX/R12-R15, original argv pointer and clean production allocation balance. It uses GAS-linked harnesses rather than autonomous output.
- Independent second-executor final-hash PE probes were reported passing under Wine 11.22. This package's local PE runs use Wine 11.0. Neither is physical native Windows hardware coverage. Parent retains the separate executor's raw captures.
- Changing only a test PE's preferred ImageBase passed as a local diagnostic. That is not a relocation, ASLR or general rebase guarantee.
