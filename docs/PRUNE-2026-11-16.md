# Dead-helper pruning (`src/prune.rs`)

hbc emits most of its runtime helpers as fixed blocks of hand-written
assembly. Several large blocks (`HASH_HELPERS`, `CTOR_HELPERS`,
`ARRAY3_HELPER`, `F64_HELPER`, `WIN_HELPERS`) were pushed into every
program, so each new builtin made every executable bigger. A hello world grew
from 15,360 bytes (hbc of 2026-11-14) to 22,016 bytes: it carried ASCAN,
ASORT, STRTRAN, PADC, AT/RAT, the float cells and the math helpers without
calling any of them.

`prune::prune` runs on the final assembly text, for every target and for
`.s` output too, and keeps only the code reachable from `_start`:

- The text sections are split into blocks, one per non-local label.
  `.L...` labels, numeric labels and `.set` names belong to the block that
  holds them.
- A block references every symbol named in its code (`call`, `jmp`, `lea`,
  `.quad`, ...). Comments and quoted strings are ignored.
- A block whose last instruction is not `ret`/`jmp`/`ud2`/`hlt` can fall
  into the next block, so that block stays with it.
- Roots: `_start`, every `.globl` name, and every symbol named outside a
  block (data sections, text before the first label).
- Lines outside text blocks are always kept. The pass only ever drops whole
  unreachable text blocks, and keeps everything when `_start` is missing or
  an `.include`/`.incbin` appears.

`--no-prune` turns it off.

## Measured (Windows PE, native)

| Program | Before | After |
|---|---:|---:|
| hello world | 22,016 B | 5,632 B |
| `? &c` (macro) | 46,080 B | 32,768 B |
| `PRIVATE n` | 46,592 B | 32,768 B |
| tests/macro/m1-values.prg | 151,552 B | 138,752 B |
| 82 battery programs (every 15th manifest row) | mean 23,952 B | mean 8,997 B (-62.4%, range -19% to -74%) |

Two methods agree for hello world: the file size and the sum of the PE
section raw sizes plus headers (`.text` 17,552 -> 1,216 bytes). Data
sections are not pruned: `.rdata` stays at 1,856 bytes and `.bss`
(24,608 bytes, run-time memory only) is unchanged.

Program output is unchanged: the four programs above print the same bytes,
and the full native Windows battery passes with the pruned compiler (1,719
pass, 23 skip; the one failure, t1306, passes 3 of 3 runs on its own, the
known file-lock flake). Unit tests: `rustc --test src/hbc.rs`, filter
`prune` (4 tests).

## Limits

- Data is never pruned, so strings and tables of dead helpers stay.
- A data reference keeps its target alive even when the data itself is
  unused.
- `.globl` symbols are always roots.
