## Published marker: single-module INIT startup hooks

Base: `30060a185f0fc39afb05b72dd8f024a4a1922373`. The independent Rust/assembly implementation changes function parsing, startup metadata, entry-point calls and the LLVM admission boundary. The first route supports parameterless `INIT PROCEDURE` / `INIT FUNCTION` hooks with bare or NIL returns and an explicit ordinary Main in the same compilation unit. Hook symbols use the oracle-observed `$` suffix, so `ProcName()` in Boot observes `BOOT$`; an ordinary `Boot()` has its own separate symbol and does not call the startup hook. Hooks with parameters, non-NIL returns (including dead branches), or their own STATIC declarations reject explicitly. Hooks are not ordinary callable names. EXIT teardown, missing-Main fallback entry selection, external modules and cross-module hook order are not supported by this route. Active hooks reject LLVM with and without tracing, for both target profiles. Ordinary Windows startup assembly is generated and its call order is inspected, but no Windows object assembly, linking or execution was tested. Existing abort/error paths have no new cleanup or error-dialogue equivalence claim.

## Published marker: bare physical-line TEXT streams

Base: `2fc94266b77a758bdeaa80583e5bc201bf641e38`. Independent MIT Rust implementation, derived from black-box oracle measurements and original source inputs, not Harbour implementation code. Persistent-root/@STATIC validation, retention and storage are unchanged. `src/hbc.rs` changes only by a five-line LLVM frontend rejection guard. The language implementation is in `src/pp.rs`.

The unchanged upstream `tests/vec1.prg`, SHA256 `4261a61f3ef870ea3413b81f317c64b97e0308ce93373e5915579eb0daea16c9`, now compiles on the ordinary Linux backend and matches Harbour core `694428e1c12f726675b19324d62167fa77d68185`, GTSTD: 38 stdout bytes, SHA256 `08633b50d4efe218a807d9b9bd41efcfc76b946328db306667c8e395ce35afbb`, empty stderr, exit 0. The original was not edited or adapted.

This route recognizes bare, case-insensitive physical-line `TEXT` / `ENDTEXT` before comment stripping. Body lines are literal data, including leading/trailing spaces, comment-like text, macro names, directive markers and semicolons. Each body line emits one `?` literal; source origins and ProcLine mappings are preserved. An empty stream emits nothing; a blank body line emits a newline. Inactive streams emit nothing. CRLF is normalized as the existing source reader already does. The stream must close in its own file. A continuation into TEXT rejects.

The route conservatively rejects active TEXT whenever custom command/translation rules or a TEXT macro are present. Argument forms and generated TEXT remain outside this route. Body lines containing control characters or more than 79 UTF-8 bytes reject explicitly. The 79-byte boundary has an exact oracle positive, and the 80-byte and TAB inputs have rejection fixtures. A literal TAB oracle experiment exposed an existing terminal-presentation difference; it was not recorded as a compatibility pass. This is bounded literal-stream support, not general terminal emulation or the full TEXT command family. Known fail-closed over-rejection: an unterminated TEXT opener inside an inactive region (for example `#if 0`, `TEXT`, `#endif`) is rejected by the physical-line prepass even though the Harbour oracle skips it and continues. The independent reviewer found this conservative boundary; none of the 1041 originals exercises it. It remains an explicit limitation, not equivalence for that input.

Active bare TEXT rejects explicitly under both LLVM target profiles, including the no-trace profile. An early LLVM probe silently lost two trailing spaces before a following QQOut; this candidate fails closed rather than claiming equivalence or changing LLVM string semantics. A wholly inactive TEXT stream does not activate that guard and still runs exactly on LLVM Linux. Windows LLVM object generation for that inactive case is checked, not executed.

## Published marker: read-only string byte iteration

Base: `3af4c7a666d2730bbe3554d616f739ff3479c743`. This increment changes no persistent-root/@STATIC validation, retention or storage rule. The compiler changes are string iteration, a narrow value-call copy for proven string-iterator observers, and output presentation. Implementation is independent Rust/assembly; no Harbour implementation code is imported.

The unchanged upstream `tests/test.prg` (303 bytes, SHA256 `e99e9fa8d9364a9aa805996e1f28bb12ceb36a3b5ee448198e3121c5dfc8dc7e`) now compiles and matches Harbour core `694428e1c12f726675b19324d62167fa77d68185`, GTSTD on Linux: stdout 170 bytes, SHA256 `ccb7248bada94ea9429d1f6251eae5e322d63b20ff630e287d31e86c87457439`, empty stderr, exit 0. `FOR EACH` borrows a string variable and observes each byte as a one-byte borrowed string. NUL bytes remain part of its length and produce `Asc(x) == 0`. This first string route permits printing, pure scalar/string observations, `IF`, `EXIT`, `LOOP` and bare `RETURN` only. Storage, assignment, capture, user calls, nested iteration and temporary collections reject, including in dead branches. This is not general mutable character enumeration or Unicode-codepoint iteration.

A single-parameter procedure proven syntactically to consist only of NIL local declarations, observation-only iteration with `Asc` evidence, and bare/NIL returns receives an owned string copy on ordinary value calls. The caller retains its named value; computed input temporaries are freed after copying. The callee uses the existing owned-string ABI and cleanup. Omitted or explicit by-reference arguments to that narrow observer route reject. Other procedures retain their previous move rules.

GTSTD renders NUL as `.` for `?`/`??`/QOut/QQOut. This is presentation only: bounded stack scratch leaves source bytes and ownership unchanged. OutStd/OutErr retain raw NUL. The stderr helper generator now uses the raw writer, stops requesting the already-removed `dynlit` helper, and includes numeric-local F64 with distinct local labels. This also fixes the inherited OutErr compilation panic. Other GTSTD control characters, 80-column wrapping and terminal behavior remain unclosed.
