# Peephole pass over the generated assembly (19 November 2026)

hbc's expression code generator is a stack machine: a left operand is
spilled through the machine stack while the right one is computed, every
value travels as a 16-byte pair, and statement lowering leaves double jumps
and jumps to the next label. Compared with rustc/LLVM on the same small
function (`fib`, recursive, integer), main emitted 91 instructions for the
body against 47 for rustc `-O0` and 19 for `-O3`.

`src/peep.rs` is phase 1 of tightening that output: a pass over the final
assembly text, after `src/prune.rs`, that rewrites exact local patterns.
`--no-peephole` turns it off.

| rule | pattern | result |
|---|---|---|
| R1 | `sub $16,%rsp; mov %rax,(%rsp); M*; mov (%rsp),%rcx; add $16,%rsp` (and `push %rax; M*; pop %rcx`) | `mov %rax,%rcx; M*` |
| R2 | 16-byte rax:rdx store reloaded at once from the same cell and released | dropped |
| R3 | `jmp` right after an unconditional `jmp`/`ret` | dropped (dead) |
| R4 | `jmp .Lx` followed only by labels, one of them `.Lx` | dropped |
| R5 | `jCC .La; jmp .Lb; .La:` | `jNCC .Lb; .La:` |
| R6 | `add $16,%rsp; sub $16,%rsp` | dropped |

`M` lines may only load an immediate or an `rbp` slot into rax/rdx (or xor
them): they read neither rsp, rcx nor the spilled cell. Labels are never
removed and no rule crosses a label. Lines with comments never match.
Every output form (`mov %rax,%rcx`, the inverted `jcc`) was already emitted
elsewhere, so the ELF, PE, Mach-O writers and the ARM64 translator see no
new instruction shapes.

## Measured (native Windows 11, 19 November 2026)

- `fib` body: 91 -> 73 instructions (two independent counts agree).
- `fib(35)`: 198 ms -> 164 ms, best of 9, two rounds identical.
- A loop of `s += i % 7` is unchanged (1571 ms): its time is in the
  float `%` path, which this pass does not touch.
- All programs under `tests/` and `extend/demo` (1883 compiles,
  Windows target, before R6): instruction lines -0.7 %, PE bytes -0.3 %;
  most of each program is runtime helpers, which keep their shape.

## Verification

Differential run on every runnable manifest row (1262 rows at main
`6b70b06b`): each program compiled by main's compiler and by this one to
a Windows PE (internal writer), run natively, and stdout, stderr and exit
status compared: 1262/1262 identical, plain and with `--instrument`
(11 rows do not compile for Windows with either compiler). The Linux ELF
of every row was also assembled by both compilers with the same result.
The CI gates run the full battery on Linux, Windows and the macOS runners.

## Not in this phase

Unboxed integer locals in registers, register argument passing, trace
updates only before fallible operations, integer `%`. Those change the
code generator itself, not its text.
